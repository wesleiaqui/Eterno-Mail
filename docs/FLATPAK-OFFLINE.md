# Flatpak offline build status

The future Flathub manifest is
`build/flatpak/flathub/io.github.wesleiaqui.EternoMail.yml`. It is the only
release manifest and must use a real `vX.Y.Z` tag and its immutable commit.
Until the first Eterno Mail tag exists, it is deliberately not suitable for a
local release build. At present its `v0.3.3` tag and pinned commit do not
exist in `wesleiaqui/Eterno-Mail`, so Flatpak source acquisition cannot resolve.

For local packaging of the current checkout, use the prebuilt development
manifest through `build/flatpak/build-local.sh`. It packages a locally built
`eterno-mail`; it is not a Flathub submission path.

`io.github.wesleiaqui.EternoMail-source.yml` is a legacy source experiment. It
uses network-dependent commands and Wails `@latest`, so it must not be used for
Flathub or release validation.

## Release-manifest dependency inputs

The release manifest builds the frontend with `npm ci --offline`; its npm cache
sources are generated from `frontend/package-lock.json` by:

```bash
python3 build/flatpak/flathub/gen-node-sources.py
```

Run it whenever the lockfile changes and commit both files. It only translates
the lockfile into hash-pinned source entries; it does not update dependencies.

Go dependencies are supplied as source archives in `go.mod.yml` plus
`modules.txt`, generated by `github.com/dennwc/flatpak-go-mod`. Regenerate both
with a pinned copy of that generator whenever `go.mod` or `go.sum` changes.
The generator is not installed in this checkout's environment, so the current
Go source list must be regenerated before a Flathub build: it still references
Wails v2.13.0 while `go.mod` requires v2.15.0.

The release manifest uses direct `go build -mod=vendor`, not the Wails CLI:
the frontend is built first, then embedded by Go. No Wails CLI is required in
the sandbox. GitHub release builds pin their separate Wails CLI installation to
v2.15.0.

## Public OAuth client configuration

Google and Microsoft desktop OAuth client IDs are public configuration and are
intentionally included in source for reproducible Flatpak builds. Google may
also require the value it labels `client_secret` for a Desktop client; that
value is not confidential in a distributed desktop application. Its final
publication strategy remains an explicit release decision. User tokens are
never included. The build has no credential helper or precompiled OAuth
artifact.
